# DECISIONS

Append-only. Each entry records what was decided, why, and what it cost. A
reversed decision gets a **new** entry that supersedes the old one — the old
entry stays, because reasoning that turned out to be wrong is the most useful
part of the record.

Format: `D<nnn> — <title>` / date / status / the decision / why / consequences.

---

## D001 — Projects are user data, the repo is the engine

**2026-07** · standing

`projects/` and `public/videos/` are gitignored. The tracked tree is `src/`,
`scripts/`, `docs/`, the skill and config — the parts that are identical for
everyone.

**Why:** a video is the user's work and their recording. Tracking them would
make the repo unshareable and would put audio in git history forever.

**Consequences:** `src/Root.tsx` cannot import projects by name, so composition
registration has to be generated by scanning the directory (see D003). It also
means **there is no undo for anything under `projects/`** — git cannot restore
it. Changes to project files are therefore held to a higher bar than changes to
engine files, and bulk rewrites across `projects/` are avoided where the same
benefit can be had by changing the engine.

---

## D002 — One theme (`gizmo`), not ten

**2026-07-31** · active

Deleted `neon`, `paper`, `brut`, `midnight`, `garage`, `debugview`, `ps1`,
`cosmic`, `nightdrive` and `theme/defaults.ts`. Repointed the four projects that
named a deleted theme at `gizmo`.

**Why:** usage was `gizmo` ×7, `midnight` ×2, `nightdrive` ×1, `cosmic` ×1 —
six of the ten had shipped nothing. Meanwhile every new token in
`theme/types.ts` cost ten hand-written blocks to add. That tax is what made
profile-aware type sizing expensive enough to keep deferring, which in turn is
what blocked landscape and therefore long-form.

**Consequences:**
- The token contract in `theme/types.ts` is unchanged and still enforced. What
  went away is the *cross-product*, not the indirection.
- `crt` and `glass` token groups are now set but disabled (`enabled: false`).
  `kit/Crt.tsx` and the glass paths are kept — the effects worked and were hard
  to get right — but nothing renders them today.
- It also fixed a live inconsistency: `src/theme/index.ts` had
  `DEFAULT_THEME = 'cosmic'` while `scripts/sync-projects.ts` had `'gizmo'`.
- Composition ids stay `<slug>-gizmo` rather than collapsing to `<slug>`, so
  existing muscle memory and script invocations keep working.

**Superseded:** the previous position, recorded in the old `style.md`, was that
`garage`/`debugview`/`ps1` existed because the first four themes read "too
clean, corporate for a personal gamedev account". That diagnosis was correct but
the remedy was wrong — the fix for a flat video is a better picture, not a new
skin. See D004.

## D003 — Compositions are discovered, not declared

**2026-07** · standing

`scripts/sync-projects.ts` scans `projects/`, and writes
`src/registry.generated.ts`, which `Root.tsx` turns into compositions. Adding a
video never touches engine code.

**Why:** forced by D001 — the set of projects differs on every checkout.

**Consequences:** the generated file is gitignored and regenerated by pre-hooks
on `studio`, `render`, `check` and `typecheck`, so it is never stale in practice.

## D004 — A skin cannot rescue a weak vocabulary

**2026-07** · standing

The first eight themes were one design with eight paint jobs. The cause was not
the theme system: the kit could only draw **one shape** — a rounded rectangle
with a label and a body. `TitleCard`, `Box`, `Callout`, `CodePanel` and
`Compare` are all that rectangle in a column. Varying fill, border, radius, font
and easing cannot make two identical compositions look different.

**The fix was a second vocabulary** — the scene system, where the picture is the
explanation rather than a container for sentences — plus `theme.draw`, which
controls how a theme *draws* rather than how it colours.

**Consequences:** when a video looks flat, the fix is a better picture. This is
the reasoning behind scene-first being the default in FORMAT.md.

## D005 — The pipeline is a DAG with enforced ordering

**2026-07** · standing

`scripts/build.ts` runs stages in dependency order and skips those whose inputs
have not changed.

**Why:** the pipeline's failure mode is silent. Re-record a voiceover, forget to
retime, and you get a finished video captioned from the previous take. Nothing
errors.

**Consequences:** staleness is mtime-based with two deliberate exceptions, both
because `beats.yaml` is *both* an input and an output of the pipeline:
- the `vo:` block is **hashed**, so retime's duration rewrites do not re-run the
  audio chain forever;
- the alignment key (every beat's id and `vo` line, plus `corrections`) is
  **hashed**, so a rewritten narration line re-transcribes but a rewritten
  duration does not.

`vo.wav` is additionally identified by `mtime:size`, so a take dropped in by
hand is distinguishable from one this pipeline produced — an unprocessed take is
a *different length* from a processed one, and transcribing it first puts every
caption timestamp out by the silence trim.

## D006 — A human gate between transcribing and captioning

**2026-07-30** · standing

`build` stops after transcription, writes `transcript.md`, and requires another
invocation to apply it.

**Why:** the transcript becomes the burned-in caption text, and whisper's
mistakes are function words that a larger model cannot reliably fix. A build
that transcribed and carried straight on would put unchecked words on screen.

**Consequences:** builds with a new recording always take two invocations. This
is deliberate friction.

## D007 — Long-form is a different product, and unproven

**2026-07-31** · active

Long-form is capped at 5 minutes, educational deep dives only, landscape, no
burned-in captions, one narration file supplied by the user.

**Why the caution:** the risk is not per-shot animation quality — that is
demonstrated by the shipped shorts (`flow-field` is 1094 lines of bespoke sim
and scene code; `gimbal-lock` 698 with real quaternion math). The risks are:

1. **Coherence across ~40 beats.** An agent's context is summarised during a
   build that long; chapter 1's visual language is genuinely not in memory by
   chapter 5. Unmanaged, this produces drift nobody notices until a full watch.
2. **Editorial judgement across 5 minutes.** No agent can watch video. Machine
   checks catch a 22-second static hold; they cannot catch "the argument stopped
   developing at 3:20".
3. **Volume.** ~6× the building, with compounding errors.

**Consequences:** long-form machinery is gated behind a **one-chapter pilot**
rather than built speculatively. The chapter split and the shot list are not
process for its own sake — they are the specific mitigation for risk 1, because
an external artifact that gets re-read survives context compaction and an
agent's memory does not.

## D008 — `out/` is per-slug, with deliverables separated from debris

**2026-07-31** · active

`out/<slug>/{qa,renders,deliver}` replaces a flat `out/`. `npm run clean`
removes the disposable parts. Scratch renders go in `qa/`, never at `out/` root.

**Why:** the flat directory accumulated 53 files in `checks/`, ad-hoc probe PNGs
at the root, and `flow-field-gizmo (Copy 2).mp4` through `(Copy 3).mp4`.
Deliverables and debris were indistinguishable, and nothing told an agent where
to put a throwaway render — so they went anywhere.

**Consequences:** renders are numbered rather than overwritten, so a re-render
never silently replaces a good take and never needs a manual `(Copy)`.
`deliver/` holds one file per video and is the only directory the user needs to
look at.

## D009 — Mechanical QA is a script, not an agent reading images

**2026-07-31** · active

`npm run check <slug>` renders sample frames, measures every text and panel node
against the layout profile, and reports violations as text.

**Why:** the previous QA loop had the agent read a contact-sheet PNG after every
scene edit. Each read costs image tokens, the loop runs many times per video,
and most of the checklist is objectively measurable — overflow, collisions,
safe-area violations, captions outside the band, static holds. Using a language
model as a pixel inspector is both expensive and less reliable than arithmetic.

**Consequences:**
- The contact sheet survives for the one check that genuinely needs eyes: *does
  the picture make the point?*
- The check gets **better** at long-form length, where a 12-frame contact sheet
  gets worse — 12 samples across 5 minutes is one per 25 seconds and misses
  entire beats.
- Static-hold detection doubles as the engagement metric in FORMAT.md.

## D010 — Type sizes are a profile-resolved scale, not theme constants

**2026-07-31** · active

`theme.type.size` holds **ratios**; the layout profile supplies the base size in
px. `useType()` resolves them.

**Why:** sizes were absolute px "at 1080x1920". An 88px title is 4.6% of a
1920-tall frame and 8.1% of a 1080-tall one — the same theme in landscape
produced type a third too large, and nothing said so. This is what actually
blocked landscape, not the bounds arithmetic, which was already correct.

**Consequences:** a theme now describes *proportion*, which is what a theme
should describe. Adding a profile no longer requires touching the theme.

## D011 — The kit has three tiers and a rule of three

**2026-07-31** · active

- **Frame** — `Stage`, `Beat`, layout, theme, captions, music. Shared, stable,
  high bar to change.
- **Primitive** — parameterised mechanisms: `Scene`, `Field`, `Plot`, `Lanes`,
  `Split`, `Scene3D`, `useSim`, code panels.
- **Video-local** — bespoke composition, lives in `projects/<slug>/`. Promotion
  to the kit requires a **third** user, not a first.

**Why:** the old rule was "if the kit lacks something, add it to the kit first".
Measured, that produced a kit where `Stage` and `Beat` had 12 and 11 users, a
scene core had 4–6 each, and **twenty-plus components had one or two** — while
each project separately defined 12 to 43 local components anyway (flow-field:
43). The rule pushed one-offs into shared code without preventing the bespoke
work, so the kit became a museum of single-user components that every future
session had to read past.

**Consequences:**
- Existing single-user components were **not** evicted. They work, and D001
  means changes under `projects/` have no undo — the churn would carry real risk
  for no functional gain. They are marked instead, and not to be extended.
- The saving comes from tiering the *export surface and the reference doc*, so a
  session reads the tier it needs rather than all forty exports.

## D012 — Provenance is tracked by content identity, never by mtime

**2026-08-01** · active

`process-vo` records the identity (`mtime:size`) of the `vo.wav` it wrote, in
`public/videos/<slug>/.vo-state.json`. When it cannot tell what a `vo.wav` is,
it **refuses and asks** (`--adopt` / `--reprocess`) rather than guessing.
`build.ts` no longer runs `process-vo` merely because it has no state file.

**Why:** the previous rule was "a `vo.wav` newer than `vo.raw.wav` is a new
take". That is unsound, because this script READS the raw and WRITES the output
— so the output is *always* newer after a normal run, and the 1-second tolerance
was far short of the time it takes to encode 100 seconds of audio.

It went unnoticed because `build.ts` tracks a content stamp and normally
prevents a second consecutive run. Then a project turned up with no
`.build-state.json`; `build.ts` ran `process-vo` "to establish the stamp";
`process-vo` had nothing to compare against either, and **adopted its own
processed output as the untouched original**. Two scripts guessing at once, and
the one unrecoverable action in the pipeline taken automatically.

Damage was contained — the archive copy (`vo.raw.<stamp>.wav`) held the true
106.1s original, and reprocessing from it reproduced `vo.wav` to the same
98.648s and every beat duration to `+0.00`. Nothing was lost. It was luck that
the archive existed, not design.

**Consequences:**
- Unrecoverable actions are never taken on a guess. Asking costs seconds; a
  destroyed take costs a recording session.
- Where two components can each infer the same fact, exactly one owns it.
- **Known rough edge:** reprocessing audio without re-recording moves `vo.wav`'s
  mtime past `transcript.md`, so the build wants to re-transcribe even though
  the content is unchanged. The real fix is to stamp the transcript with the
  audio identity it was made from, the same way everything else here now works.
  Until then the workaround is `touch transcript.md`.

## D013 — A caption may be awkward. It may never be false. {#d013}

**2026-08-01.** The phrase grouper prices a break that would strand a negation
(`not`, `n't`, `never`, `cannot`, …) at 44, three times the cost of an ordinary
stranded function word, and prices a break *before* one at 3, below a plain
break. Negations lead their own scope.

**Why:** `second-listener` shipped with a caption reading "a very good
solution," held alone for a second and a half over the naive code, while the
voice said "this is **not** a very good solution." On Shorts and Reels most
viewing is muted, so for most of the audience the video asserted the opposite of
its own argument at the moment it was making it.

Every other rule in `phrases.ts` is about a caption looking broken. This one is
about a caption *being wrong*, and the two do not belong in the same cost tier —
`not` had been priced at 14 alongside `the` and `of`, which was not remotely
enough to outbid the flat-bottomed length cost.

**Consequences:**
- Pinned by `src/kit/captions/phrases.test.ts`. Caption rules are correctness,
  not taste, and get tests like any other correctness rule.
- Forbidding the bad break is only half of it — the good break has to be made
  cheap, or the grouper just finds a different bad one ("Now this is not a").

## D014 — A beat boundary is not a free break. {#d014}

**2026-08-01.** `breakCost` returns 6 rather than 0 when there is no next word,
and `unstrandConnectives` pushes a trailing `and` / `but` / `so` / `when` across
a beat split into the beat it opens.

**Why:** the old comment read "the break is already forced, so it is free." The
break is forced; where the phrase *before* it starts is not, and charging
nothing meant the grouper could not tell a segment ending on a full stop from
one ending on "and". Six of seven beats in `second-listener` ended on a stranded
conjunction.

`snapToSentences` already handled the case where the boundary sits a word away
from a full stop. It cannot help when the read runs on and there is no full stop
within reach, which is exactly what an improvised take produces. The grouper
cannot help either — a word can only be grouped inside the segment it was given
— so the repair has to happen at the split.

**Consequences:**
- Both passes only ever move a split across words already spoken adjacently, so
  no timing is invented; a word changes which caption it belongs to, never when
  it appears.
- `snapToSentences` wins where they disagree: a split already on a full stop is
  correct and is left alone.

## D015 — An arrow ends where the arrow ends. {#d015}

**2026-08-01.** `Graph` draws an edge as **two** line segments with the
arrowhead's own footprint removed from between them, rather than as one full
line with a head laid on top.

**Why:** the head was a triangle centred on a point 93% along a shaft drawn to
100%, so seven percent of line plus half a head-length protruded through the
point of every arrow in every diagram. It reads as a rendering fault, and it was
in all of them.

The obvious repair — trim the shaft at the end the head points to — is wrong
here, because the head does not stay at an end. It slides the whole length of
the wire during a reversal, which is the best two seconds in `second-listener`.
Trim the far end to a head sitting halfway along and the wire visibly retracts
from the box it is pointing at: a worse artefact than the overshoot, and it was
rendered and caught before it went anywhere.

Cutting out only what the head covers is correct at every position the head can
occupy. At an end, one segment is empty and the other stops at the head's base.
Halfway, both exist and meet where the head is, so the wire stays continuous —
which it must, because mid-turn the head is edge-on and there is nothing there
to hide behind.

**Consequences:**
- `npm run check` cannot see this class of defect and correctly reported the
  video clean throughout. Geometry validation is not a substitute for looking at
  frames.
